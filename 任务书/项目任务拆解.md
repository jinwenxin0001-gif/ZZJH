# 邮件网关云地协同防御技术研究——高校创新项目任务拆解

## 1. 项目约束与执行原则

| 项目 | 条件 |
|---|---|
| 项目性质 | 企业面向高校研究生的创新资助项目 |
| 项目周期 | 12 个月 |
| 项目经费 | 6 万元 |
| 核心人员 | 2 名研究生 |
| 交付定位 | 覆盖任务书全部需求的研究原型，不按企业商用产品标准交付 |

本项目采用以下执行原则：

1. **任务书需求全部覆盖**：每项研究内容和交付物均有对应模块、原型功能和验证方式；
2. **实现深度合理收缩**：通过开源组件复用、插件化适配和限定支持范围控制工作量；
3. **突出研究创新**：重点投入多模态密码提取、身份与内容联合检测、云地协同快慢路径三项研究；
4. **原型代替商用品质**：完成可运行、可演示、可测试的闭环，不承诺生产级高可用和全格式兼容；
5. **指标必须可复现**：所有性能和算法指标均绑定固定数据集、硬件环境和测试负载。

## 2. 任务书需求覆盖矩阵

| 任务书要求 | 对应模块 | 高校研究原型的实现边界 | 验证方式 |
|---|---|---|---|
| 支持 SMTP/POP3/IMAP | M2 | SMTP 基础接收与转发；POP3/IMAP 采用连接器拉取邮件，不自研完整协议服务端 | 三种协议各完成端到端样例演示 |
| 正文和图片密码提取 | M3 | 规则、OCR、轻量 NLP 与候选排序 | Top-K 召回率与消融实验 |
| Office/PDF 中密码提示提取 | M3 | 支持常见文本、文本框和可解析对象，不追求所有文档版本 | 分类场景测试 |
| Zip/RAR 等加密附件自动解密 | M3 | 至少支持 Zip、RAR、7z 中两类，限制尝试次数和展开资源 | 自动解密成功率 |
| 云地协同威胁情报 | M5 | 本地检测 + 2 个在线情报源 + 1 个本地/模拟内部 TI 适配器 | 多源查询与超时降级演示 |
| SOAR 插件化编排 | M5 | 实现轻量插件接口、并行查询、缓存、超时与结果聚合，不建设完整 SOAR 平台 | 新增插件及编排流程演示 |
| 云端沙箱投递 | M5 | 接入 1 个可用沙箱接口；无正式额度时使用录制响应完成可复现实验 | 样本提交、结果回收与关联演示 |
| 高并发流式处理 | M6 | 复用 MTA 和消息队列，构建单机或小型双节点研究原型 | 固定负载下的吞吐和延迟曲线 |
| Go/Rust、Redis/Kafka 等技术 | M2、M6 | 接入层优先 Go，算法层 Python；Redis Streams 或 Kafka 选择一种 | 架构说明及运行演示 |
| SPF/DKIM/DMARC 分析 | M4 | 使用成熟库完成验证和对齐分析 | 协议测试样本 |
| Received 头部分析 | M4 | 检查路径、时间顺序、中继和来源异常 | 正常与伪造案例测试 |
| 身份伪造检测和可信度评分 | M4 | 融合协议、字段一致性、域名和内容特征 | 分类指标与案例解释 |
| 高信誉域名滥用检测 | M4 | 将合法认证结果与欺诈语义、URL 风险联合判断 | 专项对照实验 |
| Office/PDF/压缩包 CDR | M5 | 各完成一种可演示的基础清洗策略，不追求商用级版式保真 | 清洗前后安全性和可用性测试 |
| 安全检测与投递解耦 | M6 | 本地快速路径与 OCR、沙箱、情报慢路径分离 | 快慢路径延迟对比 |
| 放行、隔离和清洗后投递 | M6 | 实现三类核心决策及简单审计记录 | 端到端场景演示 |
| 四项技术考核指标 | M7 | 明确统计口径并形成自动化测试脚本 | 综合测试报告 |

由此，本方案不删除任务书中的功能要求，只降低每项功能的工程化深度和兼容范围。

## 3. 项目目标与范围

### 3.1 必须完成的目标

- 建立邮件安全研究数据集及可复现实验流程；
- 实现支持 SMTP、POP3、IMAP 的轻量邮件接入原型；
- 完成 MIME、正文、图片、URL、Office/PDF 和压缩附件解析；
- 实现图文及文档密码线索提取和候选排序；
- 实现加密压缩包自动解密和安全展开；
- 实现 SPF/DKIM/DMARC、Received、显示名和域名身份分析；
- 实现钓鱼语义、URL 风险和高信誉域名滥用检测；
- 实现多源威胁情报插件和轻量 SOAR 编排；
- 接入云端沙箱或建立可复现的沙箱适配实验；
- 实现 Office、PDF、压缩包的基础 CDR 清洗演示；
- 实现高并发异步处理原型和投递决策；
- 完成算法、功能、吞吐、延迟和误报率评测。

### 3.2 可选增强目标

- 增加二维码密码识别；
- 增加嵌套多层压缩包处理；
- 建立简单发件人历史画像；
- 增加第二种消息队列的对比实验；
- 增加更多情报源或真实内部 TI；
- 形成论文、专利或软件著作权成果。

### 3.3 不属于本项目验收范围的企业化能力

以下内容不是对任务书功能的删减，而是对商用工程深度的限制：

- 不自研完整 MTA、POP3 或 IMAP 服务端，优先复用成熟组件；
- 不承诺 7×24 小时生产 SLA；
- 不建设多机房灾备、多租户计费和自动扩缩容；
- 不覆盖 Office/PDF 的全部历史版本和复杂版式；
- 不自研动态恶意代码沙箱；
- 不建设完整 SOC、工单、复杂权限和大屏系统；
- 不开展真实生产邮件的自动阻断，除非企业另行提供隔离测试环境。

## 4. 拟研究的关键问题

### 4.1 多载体密码候选生成与排序

研究如何联合正文显式线索、隐式描述、图片 OCR、Office/PDF 文本、附件名称和邮件上下文生成密码候选，并通过轻量模型或排序方法提高 Top-K 召回率。

### 4.2 身份证据与欺诈语义联合检测

研究如何融合 SPF/DKIM/DMARC、Received 路径、From/Reply-To/Return-Path 一致性、相似域名、URL 和正文语义，以识别“协议认证合法但内容恶意”的高信誉域名滥用场景。

### 4.3 有限资源下的云地协同快慢路径

研究本地快速规则、轻量模型与耗时 OCR、附件解密、外部情报、云端沙箱之间的任务拆分，比较不同策略对吞吐、延迟和检测率的影响。

## 5. 研究原型总体架构

```text
SMTP 接收 / POP3、IMAP 拉取 / .eml 导入
                    ↓
           邮件标准化与 MIME 解析
                    ↓
       ┌────────────┼────────────┐
       ↓            ↓            ↓
多模态密码提取   身份协议分析    正文与 URL 检测
       ↓            └──────┬─────┘
加密附件解密              ↓
       ↓            本地快速风险结果
文件静态分析              ↓
       ├────→ 多源情报 SOAR 查询
       └────→ 云端沙箱分析
                    ↓
          CDR 清洗与风险结果融合
                    ↓
           放行 / 隔离 / 清洗后投递
                    ↓
             结果展示与实验评测
```

建议技术组合为：成熟 MTA 或邮件库 + Go 接入/调度 + Python 算法服务 + Redis Streams 或 Kafka + SQLite/PostgreSQL。最终选型以团队现有能力为准，不要求同时使用所有技术。

## 6. 模块化任务拆解

### M1：研究基线与数据集建设

**目标**

明确场景、指标和数据边界，为算法研究和系统测试提供统一基础。

**主要任务**

1. 调研多模态密码提取、邮件身份认证、钓鱼检测、CDR 和流式处理研究；
2. 收集公开正常邮件、公开钓鱼邮件和人工构造邮件；
3. 构造正文、图片、Office/PDF 密码提示及加密压缩包样本；
4. 构造 SPF/DKIM/DMARC、Received、显示名冒充和高信誉域名滥用场景；
5. 对样本进行脱敏、去重和标签标注；
6. 划分训练集、验证集和测试集；
7. 固化算法指标、性能负载和实验环境。

**建议数据规模**

- 邮件总量：1000～2000 封；
- 加密附件邮件：300～500 封；
- 钓鱼或仿冒邮件：400～700 封；
- 正常邮件：不少于 600 封；
- 每类核心攻击场景应有独立测试样本。

**最低完成标准**

- 数据覆盖任务书中的主要攻击与附件类型；
- 每个指标有明确分母、测试集和计算脚本；
- 真实样本不足时，公开数据与人工构造数据分开报告。

**阶段成果**

- 文献调研报告；
- 数据集与标注规范；
- 实验方案和指标说明；
- 首批研究样本。

### M2：邮件接入、协议连接器与标准化解析

**目标**

完成任务书要求的 SMTP/POP3/IMAP 支持，并向后续算法提供统一邮件对象。

**主要任务**

1. 复用成熟 MTA 或邮件库实现基础 SMTP 接收与转发；
2. 使用现有库实现 POP3 和 IMAP 邮件拉取连接器；
3. 支持 `.eml` 文件批量导入，便于离线实验；
4. 解析 Envelope、Header、纯文本、HTML、MIME 和内嵌图片；
5. 提取 From、Reply-To、Return-Path、Received、Message-ID 和认证结果；
6. 提取 URL、附件、文件类型和哈希；
7. 解析 Office/PDF 的基础文本和对象信息；
8. 定义统一邮件对象和模块接口；
9. 处理常见编码异常、畸形 MIME 和超大附件；
10. 编写三种协议接入的演示和回归测试。

**实现边界**

- SMTP 具备基础接收、暂存和转发；
- POP3/IMAP 作为客户端连接器，不实现服务端；
- 原型只在测试邮箱和隔离环境运行；
- 异常输入要求不崩溃并能记录失败，不追求所有邮件客户端兼容。

**阶段成果**

- SMTP/POP3/IMAP 接入原型；
- 邮件与 MIME 解析模块；
- Office/PDF 基础解析适配器；
- 统一邮件数据结构。

### M3：视文一体化密码提取与自动解密

**目标**

从正文、图片和 Office/PDF 中生成可解释的密码候选，并自动解密加密附件。

**主要任务**

1. 建立关键词、正则表达式和上下文窗口基线；
2. 清洗邮件正文和 HTML，提取显式及隐式密码线索；
3. 集成 OCR 识别截图、扫描件和内嵌图片；
4. 提取 Office/PDF 正文、文本框、批注等位置中的密码提示；
5. 条件允许时增加二维码内容解析；
6. 结合提示词距离、附件名称、日期、发件人等生成候选；
7. 使用规则、轻量 NLP 或排序模型对候选去重和排序；
8. 输出 Top-K 候选、置信度、来源和证据片段；
9. 支持 Zip、RAR、7z 中至少两类格式的密码尝试和解包；
10. 限制尝试次数、递归层数、展开大小和文件数；
11. 对规则、OCR、文档解析和排序方法开展对比及消融实验。

**最低完成标准**

- 正文、图片、Office/PDF 四类载体均有可运行提取流程；
- 至少两种加密压缩格式可自动解密；
- 密码结果可追溯至原始证据；
- 压缩炸弹和路径穿越样本不会破坏实验主机。

**阶段成果**

- 视文一体化密码提取模块；
- 加密附件自动解密模块；
- Top-K 召回率与自动解密实验；
- 算法对比和消融实验报告。

### M4：邮件协议、身份伪造与钓鱼欺诈检测

**目标**

融合协议、身份、URL、内容和历史信息，输出可解释的发件人可信度和钓鱼风险。

**主要任务**

1. 解析并验证 SPF、DKIM、DMARC 结果及域名对齐关系；
2. 分析 Received 路径、时间顺序、中继异常和源 IP；
3. 检查 From、Reply-To、Return-Path 一致性；
4. 检测显示名冒充、相似域名和 Unicode 同形字；
5. 提取 URL 域名、IP 链接、短链和重定向特征；
6. 建立验证码、退款、账号验证、密码重置、紧急转账等语义规则；
7. 训练或微调轻量文本分类模型作为实验对照；
8. 构造 IT、财务、HR、政府部门等冒充场景；
9. 研究“合法域名 + 欺诈内容”的联合判定方法；
10. 融合各类证据，输出身份可信度、钓鱼风险分和解释；
11. 开展单类特征与融合特征的对比实验。

**最低完成标准**

- SPF、DKIM、DMARC、Received 均进入特征和解释结果；
- 能检测至少三类常见身份冒充场景；
- 单独报告普通仿冒和高信誉域名滥用场景结果；
- 输出判定分数及命中证据，不只输出二分类标签。

**阶段成果**

- 邮件身份可信度评分模块；
- 钓鱼欺诈检测模块；
- 协议与内容融合实验报告；
- 典型误报、漏报案例分析。

### M5：云地协同 SOAR、沙箱与基础 CDR

**目标**

覆盖任务书中的多源情报、云端沙箱、结果回流及 Office/PDF/压缩包清洗要求。

**主要任务**

1. 定义 Hash、IP、Domain、URL 和文件查询插件接口；
2. 接入 VirusTotal、微步等两个可用在线情报源；
3. 以本地 IOC 库或模拟服务实现内部 TI 适配器；
4. 实现并行查询、缓存、超时、重试、限流和结果聚合；
5. 统一不同情报源的恶意分类、时间和置信度；
6. 接入一个云端沙箱，完成样本提交、轮询和报告解析；
7. 无正式沙箱额度时保存一次合法响应，以录制回放方式完成可复现实验；
8. 将沙箱行为与邮件、发件人和附件信息关联；
9. Office CDR：检测并移除宏或嵌入对象，或转换为安全格式；
10. PDF CDR：检测并移除 JavaScript、启动动作或嵌入文件；
11. 压缩包 CDR：安全解包、过滤危险文件并重新打包；
12. 保存清洗前后哈希、处理记录和失败原因；
13. 将确认恶意结果回流本地规则或 IOC 库。

**实现边界**

- SOAR 是面向本项目的轻量编排器，不提供通用可视化流程设计；
- CDR 每类格式完成至少一种代表性危险对象的处理；
- 对无法安全清洗的文件执行隔离，不强行生成可能损坏的文件；
- 云端样本上传必须使用测试样本，不上传真实敏感邮件。

**最低完成标准**

- 2 个在线情报适配器和 1 个本地/模拟 TI 适配器可统一调用；
- 1 个沙箱适配器可完成提交与结果解析；
- Office、PDF、压缩包三类对象均有基础 CDR 演示；
- 外部服务超时不会导致整个原型永久阻塞。

**阶段成果**

- 轻量 SOAR 编排引擎；
- 多源威胁情报插件；
- 云端沙箱适配器；
- Office/PDF/压缩包基础 CDR 组件。

### M6：高并发流式框架、风险决策与原型集成

**目标**

完成模块解耦、快慢路径协同和端到端决策，验证有限资源下的吞吐与延迟。

**主要任务**

1. 使用 Go 或成熟 MTA 完成轻量邮件接入和任务分发；
2. 使用 Redis Streams 或 Kafka 建立任务队列；
3. 将解析、密码提取、解密、身份检测、情报、沙箱和 CDR 拆分为任务；
4. 本地快速路径完成协议分析、规则检测和基础决策；
5. 慢速路径完成 OCR、附件处理、外部情报和沙箱分析；
6. 实现任务 ID、处理状态、简单重试、超时和失败队列；
7. 融合身份、内容、附件、情报和沙箱风险；
8. 实现放行、隔离和清洗后投递三类动作；
9. 实现简单 Web 页面或命令行界面展示结果和证据；
10. 开展不同并发数、邮件大小和附件比例下的性能实验；
11. 对比同步串行和快慢路径架构的吞吐、延迟和检测效果。

**关于高并发指标**

任务书中的“单节点 ≥ X 万封/分钟”未填写 X。项目第 2 个月前应与企业导师确认。若无法确认，本项目暂按 `X = 0.1`，即单节点每分钟 1000 封标准测试邮件作为研究原型目标，并提供完整吞吐曲线，而不宣称达到企业生产容量。

**最低完成标准**

- 邮件能够从接入端经过全部核心模块并产生最终处置；
- 快速和慢速任务可以异步运行；
- 单个外部接口失败不影响其他邮件继续处理；
- 性能结果包含硬件、邮件大小、附件比例和并发条件。

**阶段成果**

- 高并发流式处理框架；
- 风险融合与投递决策模块；
- 可运行的端到端原型；
- 并发、延迟和资源消耗实验报告。

### M7：综合评测与成果交付

**目标**

逐项验证任务书需求，形成可复现、可答辩和可移交的项目成果。

**主要任务**

1. 冻结测试集、源代码、配置、模型和依赖版本；
2. 逐项执行需求覆盖矩阵中的功能测试；
3. 评测密码候选 Top-K 召回率和自动解密成功率；
4. 评测钓鱼检测 Accuracy、Precision、Recall、F1 和误报率；
5. 评测平均延迟、P95 延迟、吞吐和资源消耗；
6. 对 CDR 清洗前后安全性、可打开性和内容保真进行测试；
7. 测试压缩炸弹、异常 MIME、超大附件和外部 API 超时；
8. 分析成功、误报、漏报和失败案例；
9. 完成安装说明、使用说明、设计报告和总结报告；
10. 整理演示视频、答辩材料以及论文或知识产权材料。

**最低完成标准**

- 任务书每项要求均有代码、演示、测试或研究结论作为证据；
- 所有实验可以通过固定脚本重复运行；
- 报告明确原型边界，不将有限测试结果表述为生产能力。

## 7. 两人分工

| 人员 | 主要方向 | 主责模块 | 具体任务 |
|---|---|---|---|
| 研究生 A | 多模态算法与数据 | M1、M3、M4 | 数据集、OCR/NLP、密码排序、文本检测、融合实验 |
| 研究生 B | 邮件安全与系统原型 | M2、M5、M6 | 协议接入、邮件解析、情报/沙箱/CDR、队列与系统集成 |

执行中应设置两个协作规则：

1. 两人共同维护统一邮件对象和端到端测试，避免算法与系统脱节；
2. 每两个月进行一次范围评审，新增任务必须替换等量的可选任务，不能持续叠加。

## 9. 建议考核指标

任务书未填写具体指标值。下表用于项目规划，最终应由企业导师和校内指导教师确认。

| 任务书指标 | 建议统计口径 | 建议目标 |
|---|---|---:|
| 加密附件自动解密成功率 | 支持格式且密码线索存在于受支持载体中的成功比例 | ≥ 75% |
| 密码候选 Top-5 召回率 | 正确密码出现在前 5 个候选中的比例 | ≥ 85% |
| 钓鱼邮件检测准确率 | 固定测试集上的 Accuracy | ≥ 90% |
| 钓鱼检测 F1 | 固定测试集上的综合结果 | ≥ 85% |
| 误报率 | 正常邮件被判为高风险的比例 | ≤ 5% |
| 邮件平均处理延迟 | 本地快速路径，不含沙箱及外部 API | ≤ 1 秒/封 |
| 深度分析延迟 | OCR、附件、情报和沙箱分别统计 | 报告平均值和 P95，不设统一硬指标 |
| 单节点吞吐 | 固定标准负载、不含云端沙箱 | 暂定 ≥ 0.1 万封/分钟 |
| 样本静默丢失 | 批量测试中无错误记录且未产生结果 | 0 |

实验报告必须说明处理器、内存、网络、邮件大小、附件比例、并发数、缓存状态和外部 API 条件。

## 12. 主要风险与应对

| 风险 | 应对措施 |
|---|---|
| 两人难以覆盖全部功能 | 所有需求采用最小原型深度，开源复用优先，创新模块投入主要时间 |
| 缺少真实邮件数据 | 公开数据、脱敏数据和人工构造数据组合，并分开报告结果 |
| 微步或沙箱无 API 权限 | 保留真实插件接口，使用合法录制响应或本地模拟服务完成复现实验 |
| Office/PDF CDR 复杂 | 每类完成一种代表性清洗策略，失败转隔离，不追求全格式兼容 |
| 高并发目标 X 未定义 | 第 2 个月前确认；未确认时采用 0.1 万封/分钟研究基线 |
| OCR 和模型算力不足 | 使用成熟开源模型和轻量微调，不训练大型多模态模型 |
| 外部服务影响延迟 | 快慢路径分离、缓存、超时和失败降级 |
| 原型功能过多影响研究质量 | 密码提取和身份融合是主研究线，其他模块只实现覆盖需求所需的最小闭环 |
| 敏感邮件上传风险 | 仅使用测试样本，真实邮件默认只查询脱敏 IOC |

## 13. 项目成功标准

1. 任务书全部功能要求都有可运行原型或可复现实验覆盖；
2. 三种邮件接入方式和三类最终处置能够完成端到端演示；
3. 密码提取方法相较纯规则基线有可量化提升；
4. 身份与内容融合方法相较单类特征有可量化提升；
5. 云地协同快慢路径能够展示吞吐和延迟方面的实验价值；
6. Office、PDF、压缩包均有基础 CDR 处理证据；
7. 所有任务书考核指标均有明确结果和失败案例分析；
8. 两名研究生能够在一年内完成代码、实验、报告和答辩材料。
