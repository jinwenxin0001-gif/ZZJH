# 面向高并发场景的“视文一体化”邮件网关项目任务拆解

## 1. 项目定位

本项目不是单一的钓鱼邮件分类器，而是一套面向企业邮件链路的安全处理系统。系统需要同时解决以下问题：

1. 接收并标准化解析 SMTP/POP3/IMAP 邮件及其 MIME 内容；
2. 从正文、图片、Office/PDF 文档中提取加密附件的密码线索；
3. 自动解密并递归分析压缩包和文档附件；
4. 检测发件人身份伪造、恶意链接、欺诈意图和高信誉域名滥用；
5. 调用本地检测能力、云端威胁情报和沙箱进行协同分析；
6. 对危险内容进行清洗、隔离、阻断或安全投递；
7. 在高并发条件下保证低延迟、可扩展、可审计和可恢复。

项目最终应形成“网关系统 + 算法模块 + SOAR 编排 + CDR 清洗 + 评测体系”五类成果。

## 2. 任务书分析结论

### 2.1 明确的项目目标

- 建设原型级邮件安全网关；
- 支持 SMTP、POP3、IMAP 邮件处理；
- 提供图文混合密码提取能力；
- 提供加密附件自动解密能力；
- 提供 SPF/DKIM/DMARC 和 Received 头部分析能力；
- 提供发件人可信度评分和钓鱼欺诈检测能力；
- 提供 VirusTotal、微步、内部 TI 等情报源的插件化接入；
- 提供 Office、PDF、压缩包的 CDR 清洗能力；
- 支持分布式、高并发、低延迟部署。

### 2.2 当前尚未明确的验收口径

以下内容必须在项目启动阶段形成书面基线：

| 缺口 | 影响 | 必须形成的结论 |
|---|---|---|
| 单节点“≥ X 万封/分钟”中的 X 未填写 | 无法确定容量设计和验收规模 | 明确标准邮件大小、附件比例、并发连接数和吞吐目标 |
| 自动解密成功率未填写 | 无法确定模型和密码候选策略是否达标 | 明确分母、支持格式、Top-K 候选数和目标值 |
| 钓鱼检测准确率未填写 | “准确率”易受正常邮件占比影响 | 同时使用 Precision、Recall、F1 和 FPR |
| 误报率未填写 | 无法确定生产可用性 | 明确按邮件、用户或攻击活动统计 |
| 平均延迟未填写 | 无法选择同步或异步处理方案 | 分开定义本地快速判定、附件分析和云端分析延迟 |
| “不阻塞投递”与“强制执行策略”存在冲突 | 邮件投递后无法依靠网关直接撤回 | 明确放行、暂存、隔离、清洗后投递和异步追溯策略 |
| 企业资源支持为“无” | 数据、沙箱、情报 API 和测试环境可能缺失 | 明确可用数据、API 额度、算力和测试邮件系统 |

### 2.3 建议的系统边界

- SMTP 是网关主链路，负责邮件接收、暂存、检测和转发；
- POP3/IMAP 更适合作为存量邮箱扫描或邮件拉取连接器，不应与 SMTP 转发链路混为同一性能口径；
- 本地快速检测应处于同步链路；
- 云端情报、沙箱和复杂模型应支持异步编排；
- 高风险或无法快速判定的邮件应暂存或隔离，而不是先投递后处理；
- 原型阶段优先支持 Zip、RAR、7z、Office 和 PDF，其他格式通过插件扩展。

## 5. 分模块任务拆解

### M0：需求、威胁模型与评测基线

**目标**

统一系统边界、攻击范围、数据口径和验收指标，为所有模块提供稳定基线。

**任务**

- M0-T1：梳理正常邮件、钓鱼邮件、加密附件、身份伪造和高信誉域名滥用场景；
- M0-T2：定义攻击者能力、信任边界、资产和处置策略；
- M0-T3：确定 SMTP 主链路以及 POP3/IMAP 连接器边界；
- M0-T4：定义邮件大小、附件格式、附件比例、并发量和测试负载；
- M0-T5：定义自动解密成功率、钓鱼 Precision/Recall/F1、误报率和延迟；
- M0-T6：建立邮件样本采集、脱敏、标注、划分和版本管理规范；
- M0-T7：确定第三方情报、OCR、沙箱和模型的许可及预算限制；
- M0-T8：形成需求变更和验收签字机制。

**输出**

- 《项目需求规格说明书》；
- 《邮件攻击威胁模型》；
- 《数据集与标注规范》；
- 《性能负载模型与验收指标矩阵》；
- 《处置策略矩阵》。

**验收标准**

- 所有指标均有明确分母、测试集、阈值和统计方法；
- X 万封/分钟被替换为可执行数值；
- 同步、异步、暂存和隔离边界可直接指导系统设计。

### M1：邮件接入与标准化解析

**目标**

稳定接收和解析邮件，将不同协议和复杂 MIME 内容转换为统一邮件对象。

**任务**

- M1-T1：实现 SMTP 接收、队列暂存、转发、重试和退信处理；
- M1-T2：实现 POP3/IMAP 拉取连接器，用于存量邮件或邮箱侧扫描；
- M1-T3：解析 Envelope、Header、Body、MIME、多语言编码和内嵌图片；
- M1-T4：提取发件人、收件人、Message-ID、Received 链、URL 和附件；
- M1-T5：进行文件类型识别，不信任扩展名和 MIME 声明；
- M1-T6：为邮件、正文、附件和解包文件生成稳定 ID 与哈希；
- M1-T7：定义统一邮件事件模型和模块间接口；
- M1-T8：覆盖畸形 MIME、超长头部、重复头部和编码混淆等异常输入。

**输出接口**

统一邮件对象至少包含：信封信息、协议头、正文文本、HTML、图片、附件清单、URL、哈希、解析告警和追踪 ID。

**验收标准**

- 标准样本和异常样本均不会导致服务崩溃；
- MIME 主体、内嵌图片和附件提取结果可追溯至原始字节；
- 解析失败能够隔离、告警和重试，不丢失原始邮件。

### M2：高并发流式处理底座

**目标**

建立可水平扩展、可背压、可重试且不会重复处置邮件的处理流水线。

**任务**

- M2-T1：设计接入、解析、密码提取、解密、检测、清洗和决策主题；
- M2-T2：使用 Kafka 或同类消息总线进行任务解耦；
- M2-T3：使用 Redis 或同类组件存储短期状态、缓存、限流和分布式锁；
- M2-T4：使用对象存储保存原始邮件和附件，数据库保存元数据；
- M2-T5：实现幂等键、至少一次投递下的去重、失败重试和死信队列；
- M2-T6：实现优先级队列、租户隔离、背压和过载降级；
- M2-T7：实现全链路 Trace ID、延迟分解和容量指标；
- M2-T8：完成单节点和集群压测、故障注入与恢复测试。

**验收标准**

- 节点异常不会导致邮件静默丢失；
- 重试不会造成重复投递或重复清洗；
- 队列积压可观测，超过阈值可自动限流或扩容；
- 达到 M0 确定的吞吐和延迟目标。

### M3：视文一体化密码提取

**目标**

从邮件正文、图片、二维码和文档中生成可解释的密码候选列表。

**任务**

- M3-T1：建设密码线索样本集，覆盖显式、隐晦、图片、二维码和文档场景；
- M3-T2：完成正文和 HTML 清洗、文本分段、编码修复；
- M3-T3：集成 OCR，处理截图、扫描件、旋转、压缩和低清晰度图片；
- M3-T4：解析二维码及常见机器可读码；
- M3-T5：提取 Office/PDF 文本、批注、文本框、页眉页脚和嵌入对象线索；
- M3-T6：使用规则、实体识别和上下文模型识别“密码”“口令”“见图”等表达；
- M3-T7：结合附件名称、发件人信息、日期、员工编号等上下文生成候选；
- M3-T8：对候选进行去重、排序和置信度校准；
- M3-T9：输出候选密码、来源位置、证据片段和模型版本；
- M3-T10：开展消融实验，比较 OCR、NLP 和图文融合的增益。

**输出接口**

```json
{
  "candidates": [
    {
      "value": "候选密码",
      "confidence": 0.93,
      "source": "body_image_2",
      "evidence": "图片中密码字段附近文本"
    }
  ]
}
```

**验收标准**

- 使用 Top-1、Top-3、Top-5 Recall 评估候选质量；
- 单独报告正文、图片、二维码、Office 和 PDF 场景结果；
- 输出结果可解释并可追溯到原始载体；
- 模型超时或失败时可降级为规则与 OCR 路径。

### M4：附件解密与安全展开

**目标**

使用密码候选安全地解密和递归展开附件，同时防止压缩炸弹和恶意解析器利用。

**任务**

- M4-T1：支持 Zip、RAR、7z 等压缩格式的密码验证与解包；
- M4-T2：支持受密码保护的 Office/PDF 文件；
- M4-T3：按置信度顺序尝试密码候选并限制尝试次数；
- M4-T4：处理嵌套压缩包和多层附件，生成文件关系树；
- M4-T5：限制递归深度、文件数、展开后大小、压缩比、CPU 和内存；
- M4-T6：识别压缩炸弹、路径穿越、符号链接和异常文件名；
- M4-T7：在隔离容器中执行高风险解析和解包；
- M4-T8：记录成功密码的来源和解密证据，但不在普通日志中输出明文密码；
- M4-T9：定义解密失败、格式不支持和资源超限时的处置策略。

**验收标准**

- 支持格式范围内的正常样本可稳定解密；
- 恶意压缩包无法越权写文件或耗尽主机资源；
- 自动解密成功率按“样本确有可提取密码”的条件口径统计；
- 所有解包文件均能关联回原始邮件和父附件。

### M5：身份伪造与钓鱼欺诈检测

**目标**

融合协议、身份、链接、内容和历史行为，识别身份伪造及钓鱼意图。

**任务**

- M5-T1：验证 SPF、DKIM、DMARC，记录原始结果和对齐关系；
- M5-T2：解析 Received 路径、时间顺序、中继异常和源 IP 信誉；
- M5-T3：检测显示名冒充、相似域名、Unicode 同形字和 Reply-To 不一致；
- M5-T4：提取 URL 跳转链、域名年龄、证书、重定向和页面特征；
- M5-T5：识别验证码、退款、账号验证、密码重置、紧急转账等欺诈意图；
- M5-T6：建立 IT、财务、HR、政府部门等身份冒充场景模型；
- M5-T7：构建发件人、域名、IP、主题和时间行为画像；
- M5-T8：融合规则模型和机器学习模型，输出风险分与命中证据；
- M5-T9：进行时间外测试、跨域测试和攻击族测试，防止数据泄漏；
- M5-T10：支持阈值配置和不同业务部门的策略差异。

**输出接口**

- 身份可信度评分；
- 钓鱼风险评分；
- 命中规则和模型证据；
- SPF/DKIM/DMARC 详细结果；
- 建议处置动作。

**验收标准**

- 同时报告 Precision、Recall、F1、ROC/PR-AUC 和 FPR；
- 正常内部邮件、营销邮件、自动通知和转发邮件分别评估误报；
- 对关键判定提供可供 SOC 复核的证据。

### M6：云地协同 SOAR 与威胁情报

**目标**

统一编排本地检测、外部情报和内部 TI，在受限延迟与 API 配额下返回稳定结果。

**任务**

- M6-T1：定义 Hash、IP、Domain、URL 和文件查询插件接口；
- M6-T2：接入 VirusTotal、微步和内部 TI，凭证通过密钥服务管理；
- M6-T3：实现超时、重试、熔断、限流和 API 配额控制；
- M6-T4：使用本地缓存和负缓存减少重复查询；
- M6-T5：统一不同情报源的置信度、时间戳和恶意分类；
- M6-T6：实现并行查询、条件编排和结果聚合；
- M6-T7：对上传云端的数据进行最小化和脱敏，默认不上传完整邮件；
- M6-T8：将确认结果回流规则、画像和训练样本池；
- M6-T9：记录插件版本、查询参数、响应摘要和审计信息。

**验收标准**

- 新情报源可通过插件接入，无需修改主流程；
- 单个云服务超时不会阻塞整个检测链路；
- 相同 IOC 重复查询能命中缓存并遵守服务配额；
- 情报结果包含来源、时间和可信度，不以单一来源直接定罪。

### M7：沙箱分析与 CDR 清洗

**目标**

对解密后的可疑文件进行行为分析和内容无害化处理，并保持必要的业务可用性。

**任务**

- M7-T1：定义 Office、PDF、压缩包的静态风险特征；
- M7-T2：检测宏、脚本、嵌入对象、外部模板、启动动作和可疑链接；
- M7-T3：接入云端或本地沙箱，提交样本并异步获取行为报告；
- M7-T4：关联进程、网络、文件和注册表行为与邮件上下文；
- M7-T5：实现 Office 宏和嵌入对象清除；
- M7-T6：实现 PDF JavaScript、启动动作和嵌入文件清除；
- M7-T7：对清洗前后文件进行结构、可打开性和内容一致性验证；
- M7-T8：保留原文件、清洗文件、变更清单和哈希，支持审计和回滚；
- M7-T9：清洗失败时转隔离区，不将不完整文件作为正常附件投递。

**验收标准**

- 已定义危险对象能够被移除或阻断；
- 清洗后的文件可正常打开，正文和关键版式满足保真要求；
- 沙箱超时、失败和不支持格式均有确定处置路径；
- 原文件仅对授权人员可见，所有访问留痕。

### M8：风险融合与投递决策

**目标**

将各模块证据转换为稳定、可解释和可配置的最终处置动作。

**任务**

- M8-T1：定义统一风险特征、评分区间和证据格式；
- M8-T2：融合身份、内容、URL、附件、情报和沙箱结果；
- M8-T3：实现规则优先级、冲突消解、白名单和例外审批；
- M8-T4：实现放行、加标、暂存、隔离、阻断和清洗后投递；
- M8-T5：定义快速路径、深度分析路径和超时降级路径；
- M8-T6：对高风险邮件执行 fail-close，对低风险云查询执行可配置 fail-open；
- M8-T7：生成面向用户和 SOC 的不同解释内容；
- M8-T8：支持人工复核、释放、再次隔离和策略回放；
- M8-T9：对策略和模型版本进行灰度发布与回滚。

**建议决策矩阵**

| 风险等级 | 典型条件 | 动作 |
|---|---|---|
| 低 | 协议、身份、内容和附件均无明显风险 | 直接放行 |
| 中低 | 存在弱信号但无恶意证据 | 加安全标记后放行 |
| 中高 | 加密附件无法分析、身份异常或情报待返回 | 暂存并进入深度分析 |
| 高 | 明确钓鱼、恶意附件或沙箱恶意行为 | 隔离或阻断 |
| 可清洗 | 恶意主动内容可移除且正文可信 | 清洗后投递，并附安全提示 |

**验收标准**

- 相同输入、策略和模型版本产生可重复结果；
- 所有阻断和隔离动作均能说明原因；
- 人工处置可回流为规则或训练数据；
- 不出现邮件已经投递但网关仍声明“阻断成功”的逻辑冲突。

### M9：管理、审计与运营闭环

**目标**

为 SOC、管理员和审计人员提供可视、可查、可配置的运营能力。

**任务**

- M9-T1：建设邮件检索、风险详情和证据展示页面；
- M9-T2：建设隔离区、人工复核、释放和误报反馈流程；
- M9-T3：建设策略、白名单、黑名单和插件配置管理；
- M9-T4：展示吞吐、延迟、队列积压、检测率、误报率和 API 状态；
- M9-T5：生成事件告警和攻击活动聚合视图；
- M9-T6：实现基于角色的访问控制和敏感字段脱敏；
- M9-T7：记录查询、下载、策略变更和处置操作审计日志；
- M9-T8：将确认的误报、漏报和攻击样本送入反馈数据池。

**验收标准**

- SOC 可从告警追溯至原始邮件、模块证据和最终策略；
- 未授权人员无法查看邮件正文、附件或明文密码；
- 策略变更可追踪、可回滚并能识别操作者。

### M10：安全、隐私、部署与可观测性

**目标**

确保网关自身不会成为新的攻击入口，并具备稳定部署和故障恢复能力。

**任务**

- M10-T1：服务间身份认证、最小权限和网络分区；
- M10-T2：API 密钥、证书和模型密钥的集中管理与轮换；
- M10-T3：邮件、附件和日志的传输及存储加密；
- M10-T4：敏感信息脱敏、保留期限和安全删除策略；
- M10-T5：解包器、文档解析器和沙箱的容器隔离；
- M10-T6：依赖项扫描、镜像签名、SBOM 和漏洞修复流程；
- M10-T7：指标、日志、链路追踪、告警和 SLO 看板；
- M10-T8：滚动升级、配置中心、备份恢复和灾难演练；
- M10-T9：单节点、集群和离线演示三种部署方式；
- M10-T10：编写安装、升级、运维和故障排查文档。

**验收标准**

- 高风险解析均在受限环境执行；
- 敏感凭证不会进入代码仓库或普通日志；
- 关键服务故障可自动转移或恢复；
- 可以从单封邮件追踪各模块耗时和处理结果。

### M11：测试、评测与研究成果

**目标**

以可复现实验和系统测试证明项目达到任务书要求。

**任务**

- M11-T1：建立单元、接口、集成、端到端和回归测试；
- M11-T2：建设正常邮件、钓鱼邮件、身份伪造和加密附件评测集；
- M11-T3：开展解析器模糊测试和恶意文件对抗测试；
- M11-T4：开展吞吐、延迟、长稳、积压恢复和故障注入测试；
- M11-T5：开展密码提取模型对比实验和消融实验；
- M11-T6：开展钓鱼检测时间外、跨组织和未知攻击测试；
- M11-T7：验证 CDR 的安全性、可打开性和内容保真；
- M11-T8：编制测试报告、用户手册、部署手册和技术研究报告；
- M11-T9：整理可形成论文、专利或软件著作权的创新点。

**验收标准**

- 所有任务书指标均能由自动化脚本或固定流程复现；
- 测试集、模型、规则、配置和代码版本一一对应；
- 报告同时披露总体结果、分类结果、失败案例和适用边界。

## 8. 建议验收指标基线

下表是项目启动时可讨论的建议值，不替代课题方最终确认值。

| 指标 | 建议定义 | 建议启动值 |
|---|---|---:|
| 自动解密成功率 | 支持格式内、真实密码存在于受支持载体的样本中，成功解密的比例 | ≥ 85% |
| 密码候选召回率 | 正确密码出现在 Top-5 候选中的比例 | ≥ 92% |
| 钓鱼检测 Recall | 测试集中钓鱼邮件被检出的比例 | ≥ 95% |
| 钓鱼检测 Precision | 被判为钓鱼的邮件中真实钓鱼的比例 | ≥ 95% |
| 正常邮件误报率 | 正常邮件被隔离或阻断的比例 | ≤ 0.5% |
| 快速路径延迟 | 不含外部云查询和沙箱的本地判定 P95 | ≤ 500 ms |
| 云端深度分析 | 情报与沙箱异步返回 P95 | 单独统计，不计入快速路径 |
| 单节点吞吐 | 在固定邮件大小和附件比例下的持续处理能力 | 待基准测试后填写 X |
| 稳定性 | 72 小时长稳测试期间的邮件静默丢失 | 0 |

> 说明：吞吐指标必须与平均邮件大小、P95 邮件大小、附件比例、TLS、持久化方式和检测深度绑定。仅写“封/分钟”无法形成可复现验收。

## 10. 主要风险与控制措施

| 风险 | 可能后果 | 控制措施 |
|---|---|---|
| 缺少真实邮件数据 | 模型离线效果高、真实环境失效 | 脱敏采样、时间外测试、仿真数据与红队数据结合 |
| 指标口径未冻结 | 项目结束时无法验收 | M0 未完成前不冻结架构和工期 |
| 云端 API 配额或网络不稳定 | 延迟升高、检测链路阻塞 | 缓存、限流、熔断、并行查询和本地降级 |
| 上传邮件造成隐私泄露 | 合规和数据安全风险 | 默认只查询 IOC，样本上传需策略授权和脱敏 |
| 恶意附件攻击解析器 | 网关主机被入侵或资源耗尽 | 容器隔离、资源配额、无特权运行和格式白名单 |
| CDR 破坏文档可用性 | 正常业务受影响 | 原件留存、清洗后验证、失败转隔离、支持人工释放 |
| 高并发与深度检测互相冲突 | 延迟和吞吐无法同时达标 | 快慢路径分离、异步编排、背压和容量分层 |
| POP3/IMAP 范围过大 | 主链路交付延期 | 原型阶段作为连接器，SMTP 网关优先 |
| “先投递后判定”不可撤回 | 恶意邮件已到达用户 | 高风险邮件暂存；若需投递后处置，必须接入邮箱撤回 API |
| AI 模型不可解释或漂移 | SOC 不信任、误报上升 | 证据输出、版本管理、漂移监控和人工反馈闭环 |

## 11. 最小可交付版本定义

MVP 应至少包含以下闭环能力：

1. SMTP 邮件接收、暂存和转发；
2. MIME、正文、图片、URL 和附件解析；
3. 正文与图片密码候选提取；
4. Zip/RAR 附件解密和安全展开；
5. SPF/DKIM/DMARC、显示名冒充和基础钓鱼内容检测；
6. 至少一个外部情报源的插件化查询；
7. 基于规则的放行、暂存和隔离；
8. 全链路日志、追踪、基础指标和审计；
9. 固定测试集上的自动解密率、钓鱼检测率、误报率和延迟报告。

MVP 完成后再增加 PDF/Office 密码处理、多源 SOAR、沙箱、CDR、发件人画像、模型自学习和大规模集群优化。
